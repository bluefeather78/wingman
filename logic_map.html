01

How the pieces fit together

Two jobs keep the catalog useful: finding opportunities that aren't in it yet, and making sure the ones already in it are still true. Both funnel through the same review queue and the same live table.

02

Adding new opportunities

There are two ways to discover candidates. They end up in the same place, and as of 2026-09-02 both arrive pre-checked — classified, enriched, and dedupe-hinted — so either is ready to review the moment it lands.

1

Run the Scraper Paid

Pick search angles (a general national sweep, a Seattle-area sweep, or one specific angle), and set the gate mode to Observe — it keeps every result in the queue, labelled, instead of quietly dropping or diverting anything. Cost scales with how much the model has to search; a 5-angle run has cost roughly $0.005–$0.05 per candidate found.

Console → Run → New Opportunities → Scraper
2

…or run Mine Hub Pages Paid

Leave the URL blank and set "take N from the discovery queue" to work through institution hub pages already found (see How hub leads are found below). As of 2026-09-02, a page that clears its own refusal check runs the full Scraper gate — the same refresh_opportunities extraction for the fields, the classify label, and the embedding-dedupe check — so a hub-mined row now arrives just as richly filled and just as labelled as a Scraper row. Nothing separate to run afterward.

Console → Run → New Opportunities → Mine Hub Pages
3

Catch up OLD rows: Classify, then Dedupe Paid, cheap

No longer part of the normal flow — since 2026-09-02 both the Scraper and the Hub Miner classify and dedupe every row inline (steps 1–2), so a freshly-mined row already has its label and its dedupe back-links. These queue tools stay only to catch up rows queued before that date, or to force a re-check by hand. Classify tags a row program / hub / none / stale; Dedupe checks each row's fields against the catalog vectors (see Fig. 03) — a comparison only, nothing here writes a vector. Tick "only rows already classified" on Dedupe so it doesn't re-pay for rows already handled.

Console → Run → New Opportunities → Queue tools → Classify / Dedupe
4

Triage the queue Free

Auto-rejects anything the classifier already called a hub page, not-an-opportunity, or stale — reversibly, and for no cost. Run it right before you sit down to review, so you aren't reading rows a machine can already rule out.

Console → Run → New Opportunities → Queue tools → Triage
5

Review and Activate Manual

Open the Review Queue tab. Read the classify pill, the dedupe back-links, and the quality flags on what's left, then Activate the ones worth keeping. This is the only step in the whole document that makes a row visible to a student — nothing upstream of it ever does that on its own.

Console → Review Queue
What a real run cost, measured: a 5-angle Scraper run in Observe mode turned 94 candidates into 21 queued rows for $0.4552. Because both agents now classify and dedupe inline, the separate Classify/Dedupe queue passes are only for legacy rows; for reference they cost about $0.0017/row and $0.0036 for a whole queue. Triage and Activate cost nothing. A page the Hub Miner accepts now runs the full gate — four short no-search calls (refusal + state, classify, metadata, embedding) — at roughly ~$0.004/accepted page (measured $0.0037 on one live page); a page it refuses pays for nothing after the first call.
How hub leads are found (free): two blind spots, two finders, one queue. The router spots a round-up because it links outward — a page linking ≥ 6 distinct other sites is almost always a listicle, so its programs are on those other sites and it is mined off-domain. That is blind to a university's own pre-college index, which links its programs on its own domain and looks like every other page on the site. Walk-up (wingman/walk_up_hubs.py, free) fills that half: starting from a program the catalog already trusts, it fetches the page's parent URL and asks one question — does the parent link back to the child? If yes, the parent is proven to be that program's index (never guessed from the URL's shape), and it is queued as a same-domain hub lead. It never walks up to a bare domain (a homepage is a site, not an index). Both finders write to the same discovery queue step 2 drains; the lead carries which direction to mine, because mining a same-domain index off-domain (or vice-versa) follows exactly the links that did not qualify it.

03

Keeping the catalog fresh

Six jobs quietly re-check what's already live. They don't run in sequence — each reads the same table and corrects a different slice of it, on its own schedule.

Metadata Refresh

Paid

agents/refresh_opportunities.py

Re-checks name, org, summary, eligibility and pricing — the core facts on a row. Never touches the URL; that's Link Health's job. Both discovery paths (Fig. 02) now fill these same fields at intake, so this is a periodic sanity/backfill pass, not the first fill. When a change here moves a field an embedding depends on, it re-embeds that row on the spot (both vectors, hash-gated — Fig. 03), so the vectors never drift behind the facts.

Cadence: periodic drift-check, or to backfill rows discovered before 2026-08-30

Org Reviews

Paid

agents/check_reviews.py

Checks a program's legitimacy against independent sources and stores the verdict students see. Self-limiting — it only re-checks rows unreviewed or over 30 days stale.

Cadence: safe to run anytime, does nothing if nothing's due

Action Items

Paid

agents/generate_action_items.py

Builds each row's application checklist, verified line-by-line against the program's own page. A page it can't read gets an honest generic checklist for free.

Cadence: after new rows activate

Link Health

Free

agents/check_links.py

Verifies every URL. Deactivates only what's provably gone (404 / 410 / unresolvable), flags the rest without touching it, and tries a proven repair before giving up.

Cadence: run often — weekly is fine, no cost to weigh

Mailing Lists

Free*

agents/find_mailing_lists.py

Looks for a program's signup form and proposes a recipe. Nothing goes out to a student until you promote a recipe to verified yourself.

Cadence: after a batch of activations, then verify what it found

Deadlines

Auto

agents/check_deadlines.py

Fires automatically the first time a student opens a row, cached for 7 days. You only touch this one to force a re-check or fix a known gap in a handful of rows.

Cadence: leave it alone; targeted re-checks only
Why there's no "run everything nightly" button: a full-catalog pass isn't always cheap. Measured full passes: Org Reviews ~$1.42, Action Items ~$5, Deadlines ~$84. That's why Deadlines stays on-demand and Reviews relies on its own 30-day staleness filter instead of a blanket re-check.

04

Rules to remember

The console is built so a mistake here costs seconds, not students.

👀

Preview before you pay

Every paid job has a free preview that estimates the cost before anything runs. Check it, especially the first time you try a new angle or a bigger batch.

🔒

Nothing activates itself

A scraped or mined row always lands inactive. The only way a student ever sees it is you clicking Activate in the Review Queue — every time, no exceptions.

🖥️

The console only runs on your machine

Start it with restart_server.ps1, then open http://localhost:8000/admin. It won't answer from anywhere else.

💵

Only one job is free by design

Link Health is the sole no-cost agent. The other six spend real API money per run — that's the whole reason the preview step exists.

Opportunity Dedupe Flow

Highschool Wingman · discovery pipeline

How a new opportunity is deduped

Every candidate a scraper, hub miner, name search or student turns up is checked against the whole catalog before it can reach the review queue. Two independent matchers run: a free URL/name comparison and a paid page-embedding. Only one thing they find can ever reject a row on its own.

the rule

An exact normalized URL and an agreeing name is the only signal strong enough to auto-reject. Every weaker match — same domain, similar name, high embedding cosine — becomes a hint attached to the row for a human. A wrongly-flagged row costs a reviewer ten seconds; a wrongly-rejected one is lost silently.

Reject — dropped, logged Merge — folded into incumbent Flag — kept, marked Lead — sent to hub mining Hint — back-link, never rejects Keep — enters the queue

03

Inside find_duplicates()

The Track-A cascade, checked in order against each catalog row. The first rung is the only one that rejects; the rest emit hints.

1 same match_key + name agrees (≥0.82) The one hard stop. Guarded so a bare-institution name can’t satisfy “agrees”. reject
2 same match_key, name differs / bare Same page, different name — a rename, or a shared application portal. strong
3 candidate URL == an existing row’s apply_url Different landing page, same place to apply. strong
4 same domain + one path is a sub-page of the other Real path-prefix relation, never root-vs-deep (that’s just the shared-domain problem). strong
5 same domain + name similarity ≥ 0.82 A shared host makes the name threshold safe to lower. strong
6 cross-host name similarity ≥ 0.88 ‘1-Week’ vs ‘3-Week Medical Academy’ scores 0.95 — noisy. weak
7 same domain, ≤ 3 existing rows on it “Same site” is only evidence when the domain is quiet; nyu.edu hosts 36. weak
at the feeders

All four feeders call find_duplicates(…, include_weak=False), so rungs 6–7 never reach the reviewer — they were 74% of stored hints and the least useful. The embedding track (section 02) backstops any genuine cross-host duplicate they drop.

generic names → 0
“Program”, “Summer Internship”, the extraction fallback — too generic to be evidence, so two of them never match.
bare institution → suppressed
“Tulane University” carries no program identity; two rows sharing it would falsely score 1.0, so the name signal fails open.
containment → floor 0.9
≥ 2 distinctive tokens of the shorter name inside the longer catches renames like “X” vs “Org X (ACRONYM)”.
year stripped
“ISEF 2025” and “ISEF 2026” compare equal — the same recurring program on its next cycle.

05

After it’s in the queue

dedupe_confidence fuses every signal — embedding cosine + name relation, hard-field conflicts, shared acronyms, same-institution guard — into one tier per pair. As of the 2026-09 revamp a single resolver, resolve_dup_verdict, picks the strongest pair per row and writes ONE verdict to the dup_verdict column — {confidence, best-guess survivor} — so the console shows one line, not a pile of hints. The six tiers below collapse to three operator labels: proof→Certain, confident→Likely, adjudicate/hint→Possible; sibling is hidden below a cosine floor (shown as Possible above it), none never surfaces. Auto-action stays off — every tier only labels.

Proof
Redirect or canonical URL equal — certain. Would auto-merge.
Confident
High cosine + name same + no field conflict + same institution.
Adjudicate
A qualifier or a field discrepancy — send to the LLM judge.
Sibling
Looks alike but a name/field conflict says different program. Kept.
Hint
Moderate cosine, no conflict — a back-link for a human.
None
Not similar enough — a genuinely new program.

Two queues, one resolver, never crossed: the ad-hoc detector reads ACTIVE rows and publishes to the Duplicate queue; the Review queue (pending rows) is deduped at insert. wingman/find_catalog_dups.py and the old two-step Scan→flag flow are superseded; both files stay only until the insert-time half lands.

The whole thing in one rule

Discard almost nothing; explain everything. Only five things ever remove a candidate before a human sees it — and every one is logged.

exact URL + name
The single hard duplicate.
no URL
Nothing to identify the row by.
stale program
Page’s latest cycle is years old.
hub page
Not dropped — becomes a mining lead.
not running
Page explicitly says it’s over.

Everything else — a merge aside — enters the queue with ONE verdict attached: a confidence label and a best-guess survivor. A duplicate the machine isn’t sure about is a reviewer’s ten seconds, never a silent deletion.
